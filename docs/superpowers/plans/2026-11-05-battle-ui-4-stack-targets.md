**Spec:** `docs/superpowers/specs/2026-11-04-battle-ui-design.md` (4節「複数の対象」「優先権」、7節の段階4、9節の2)

## 分け方

- **4a (0.66.0): 対象を選んで使う。** 対象を取るカード・能力を、ダブルクリック → 対象をクリックで選ぶ → 「確定」で使えるようにする。スタックの表示は、すでにある(クリックで対象にできるようにする)。
- **4b (0.67.0): 入力待ち。** 捨てるカード・選ぶカード・「してもよい」・「支払わないかぎり」・誘発型能力の対象を、画面で答える。
- **4c (0.68.0): マリガンと優先権の設定。** ロンドン・マリガン(相手の CPU は常にキープ)。優先権の止まり方(「毎回止まる」/「使えるものがあるときだけ」)を設定画面に。

## 4a: 対象を選んで使う

**設計:** `castSpell` / `activateAbility` は、もともと `targets: Record<string,string>` を受け取る。足りないのは、(1) どのノードが、何個、どれを対象にできるかを聞く入口、(2) 画面で選ぶ操作。

- `src/battle/engine.ts`: `chooseTargets` の中の「合法な対象の一覧を作る」部分を、`export function targetSlots(g, rules, item): TargetSlot[]` に切り出す(`TargetSlot = { as: string; min: number; max: number; legal: string[]; zone: string; kind: string }`)。`chooseTargets` は、これを使う(動きは変えない)。
- `src/battle/actions.ts`: `tryAction(g, rules, p, a, targets = {})`。「対象を選ぶカードは、まだ使えません」を廃止。`slotsOf(g, rules, p, a): TargetSlot[]`(カード・能力の呪文能力/能力の本体から、`item` を作って `targetSlots`)。`actionsFor` の判定は、対象を自動で補った(`autoTargets`: 各スロットの先頭から `max(min,1)` 個、`min=0` で合法が無ければ空)試し撃ち。合法な対象が足りなければ、「対象にできるものがありません」。
- `src/battle/play.ts`: `use(cardId, targets?)` / `activate(permId, index, targets?)` に `targets` を足す。`needs(action): TargetSlot[]`(画面が、選ばせるかを決める)。
- `src/battle/boardModel.ts`: `CardView` に変更なし。`BoardModel.stack[].id` はある。プレイヤーは `"you"` / `"opp"`(`g.players` の id)。
- `src/BattleView.ts` / `styles.css`: 対象の選択モード。ダブルクリックしたとき `needs()` が空でなければ、モードに入る: 合法な対象(戦場のカード・アバター(プレイヤー)・スタックの呪文)を光らせ、クリックで選択/解除、「2 / 2」の数、数が足りたら「確定」(足りない間は無効)、**Esc** で取り消し(局面は変わらない)。スロットが複数なら、順番に聞く。確定したら `use` / `activate` を `targets` つきで呼ぶ。
- テスト (`test/battle-actions.test.ts`, `test/battle-play.test.ts`, `test/battle-targets.test.ts`): ダメージ呪文(`target zone=any kind=any` + `damage`)が、マナがあれば `playable`、対象つきで唱えられ、解決でダメージ・墓地へ。打ち消し(`zone=stack`)は、スタックに呪文があるときだけ `playable`。呪禁の相手のクリーチャーは、`legal` に入らない。合法な対象が無いときは、使えない(理由つき)。`min=0` のスロットは、空でも使える。複数スロット・`max=2`。`targets` に不正な id を渡すと、RuleError で、状態は変わらない。

**Review Focus:** 対象を選んでいる間に、スタックや戦場が変わらない(自分のターンで、相手は何もしない)/ 取り消しで、ログも局面も変わらない / 対象が自分自身(カード)になるケース(自分を対象にする能力)/ 護法のある相手を対象にしたとき、護法の誘発が積まれる(エンジンの既存の動き)。

## 4b: 入力待ち (4a のあとで、詳しい計画を書く)

**方針(試作で確かめる):** エンジンは、同期のまま変えない。`BattleController` が、行動を**コピーした局面で試し**、`g.decide` が、自分(`me`)への質問で、まだ答えが無ければ `NeedInput(request)` を投げる。画面が答えを集めたら、**元の局面に戻して、答えの列を使って、最初からやり直す**(エンジンは、乱数を使わないので、同じ結果になる)。成功したら、コピーの内容を元の `Game` に書き戻す(`Object.assign`)。相手への質問は、これまでどおり、既定の動き。質問の種類: `discard` / `choose` / `may` / `pay` / `target`(誘発時)。ターンの終わりの手札を捨てる入力もここ。

## 4c: マリガンと優先権の設定 (4b のあとで、詳しい計画を書く)

- マリガン(ロンドン): 手札を見て、キープ / マリガン。マリガンは、手札を山札に戻して切り、7枚引き直し、引き直した回数だけ、底に置くカードを選ぶ(段階4aの選択の部品を使う)。相手は常にキープ(雑魚 CPU のマリガンは、段階5で、土地の枚数とコストの低いカードの有無で決める。ユーザー依頼)。マリガンが終わるまで、「次へ」は押せない。
- 優先権の設定: `settings.ts` に、「毎回止まる」/「使えるものがあるときだけ止まる」。後者は、メインフェイズでは必ず止まり、それ以外のステップでは、(土地のマナを全部出したと仮定して)唱えられる呪文・使える能力があるときだけ止まる。相手のターンも同じ。

## 私が決めたこと(直してよい)

- 対象は、必ず選んでから確定する(合法な対象が1つだけでも、自動では決めない)。
- 4b の「やり直す」方式は、エンジンを書き換えずに済むための第一候補。試作で、遅さや不具合が出たら、変える。
